# Bug review — 8 September 2026

Reviewed and updated the local checkout based on commit `59e3c87`. The review
focused on settings persistence, output routing, frontend mutations and state
delivery, and the local installer used by the standalone `.sh` package.

## Changes

| Problem | Result |
| --- | --- |
| Selecting Monitor outputs left automatic default-output following enabled, allowing the engine to override a manual choice. | Manual selection or clearing of Monitor outputs disables and saves default following. Stream output changes preserve that setting. |
| Selecting a Stream output temporarily disabled Monitor default following in the UI. | The optimistic setting update is now limited to the Monitor mix. |
| Switching from output A to B and immediately back to A could discard the final request while B was connecting. | A request to return to A now supersedes an unfinished switch. Route acknowledgements are synchronized with queue decisions. |
| Switching microphones, then returning to the original microphone or clearing the selection, could discard the last request during connection. | Input routing now also supersedes unfinished switches and synchronizes acknowledgements. |
| Concurrent saves could take snapshots before acquiring the persistence lock and write an older snapshot last. | Saves acquire the persistence lock before reading the current configuration. |
| Rapid effect edits could overlap and finish in the wrong order, with every intermediate slider position sent to the engine. | Effect writes are serialized per channel and waiting changes are coalesced to the latest value. All waiting callers are resolved or rejected, and failed writes allow later retries. |
| A delayed recovery or ordinary refresh snapshot could replace state already delivered by newer events. | Both paths preserve newer event data for each state section and fill sections whose updates were missed. Channel selection follows the merged state. |
| An EQ fader could jump to a delayed backend value while the user was dragging it. | An unfinished EQ edit keeps its local position until it is committed, then resumes following external updates. |
| An active browser app could hide a different offline app sharing the same browser process, and generic stream labels could become routing identities. | Active matching requires all saved fields, supports the backend's binary/process fallback, and excludes generic `Stream` labels. |
| Missing helpers or failed dependency checks could stop a working installation before the installer aborted. | Required helpers and dependencies are checked before stopping processes or unloading audio modules. |
| Linux screenshot tests changed with the desktop's fallback font. | Playwright uses a scoped font configuration matching the existing DejaVu Sans screenshots. The reference images and application font settings are unchanged. |
| Merging app A into B and then B into C left A resolving to B, breaking its saved route. | App identities follow the complete merge chain. Merging an app into its own alias is rejected without changing settings, and cyclic saved aliases fall back to the original identity. |
| Editing linked Monitor and Stream volumes could send overlapping requests and let an older value win. | Volume writes are serialized per channel, pending edits retain their final submission order, and older responses preserve newer local edits. Unlinked mixes retain their separate values. Recovery after a failed write waits for pending edits to finish. |
| An AppImage copy failure could stop the working app and delete or partially overwrite its installed release. | The AppImage is copied to a temporary file before shutdown, then published with an atomic rename. Failed copies preserve the existing release and remove the partial staging file, including same-version reinstalls. |
| Adaptive latency settings were normalized only when loading configuration, so saving and restarting could produce different behavior. | Settings changes immediately apply the same bounds, level cleanup, and disabled-mode normalization as configuration loading. |

The effect and volume queues reduce redundant requests and configuration writes. No claim
is made about a measured reduction in live audio CPU usage or latency.

## Validation

- The original Rust and frontend suites passed before edits.
- New regressions demonstrated failures before the persistence, Monitor
  selection, output-switch cancellation, effect queue, installer preflight,
  recovery, microphone-switch cancellation, EQ drag, routing identity, chained
  app merge, linked volume, AppImage copy, and latency settings fixes.
- The complete `scripts/test-all.sh` safe suite passed after the changes:
  515 Rust workspace tests, accelerator feature checks, 80 frontend tests,
  and 9 browser tests across 100%, 125%, and 150% scaling.
- Rust formatting, Clippy with warnings denied, TypeScript, the production
  web build, ShellCheck, documentation, dependency, packaging metadata, and
  isolated installer/ALSA alias checks passed.
- The production desktop build through `tauri build --no-bundle` passed, and
  `target/release/wavelinux6 --probe-binary` loaded successfully. This creates a
  local executable; no new AppImage or standalone installer was packaged.
- The updated audio-core release binary built successfully. Its offline
  240,000-frame stereo fixture at 48 kHz completed with zero reported underruns
  and zero fallbacks. This fixture does not validate live hardware continuity.
- Screenshot mismatches were reproduced with an untouched copy of the base
  commit. Selecting the original fallback font resolved them without changing
  the committed screenshots.
- Seven opt-in live tests remained skipped. Optional Python ONNX generation
  tooling was unavailable; the committed RNNoise model, weights, and fixture
  passed their expected hash checks.

Logs are retained locally under `target/review-results/`. ShellCheck was
provided on `PATH` from `target/review-tools/` for the safe-suite run.

## Audit scope before release packaging

During the audit, the existing `.sh`-installed AppImage and audio helper were
left in place and the running audio session was not restarted. The audit did
not include packaging or publication; subsequent release work is recorded in
`RELEASE_NOTES.md` and the GitHub release checks.

Live microphone/output hardware behavior, extended audio load testing, and
the cross-distribution package matrix were not exercised. Installer tests use
isolated files and simulated processes; the staged AppImage change does not
provide rollback of every installed helper or support file. This is a focused
review with regression fixes, not a guarantee that the entire application is
free of bugs.
